## Findings recorded on 2026-10-09

The persistence, mixed-PDF, known-name, process-containment and inference-queue findings below were addressed in the [2026-10-10 follow-up](IMPROVEMENTS-2026-10-10.md). The original findings are retained as historical evidence; the follow-up records current limits and validation.

### High: failed persistence can leave an unacknowledged mutation in memory

Commands such as `cmd_save_grade_tentative`, `cmd_import_submission` and `cmd_confirm_grade` commit the in-memory SQLite mutation before calling `DbState::persist`. If serialization or atomic file replacement fails, IPC reports an error, but the connection still contains the change. Retrying an import can produce a duplicate; retrying a save can encounter a newer revision; a process crash can lose a change subsequently visible to other reads. Encryption and atomic replacement preserve the previous disk snapshot, but do not roll back memory.

This is confirmed by the control flow, not by a disk-full integration test in this review. A follow-up should introduce one durable-mutation abstraction across all write commands, restore the pre-operation in-memory state when persistence fails, and test write, synchronization and replacement failures. Tests should verify both the immediately visible state and the reopened workspace. Do not address only one grading command, as configuration, redaction and imports share the pattern.

### Medium: mixed PDF pages can omit visible answer content

`render::visit_pdf` chooses native text whenever a page has at least ten text characters. A page with a native header and a scanned or handwritten answer will therefore skip OCR. Documents with equations or diagrams also require more than text extraction for reliable interpretation. A follow-up should detect or explicitly select mixed-page OCR and let teachers compare extracted content with the original page. Existing synthetic OCR tests cover fully scanned pages, not mixed-page completeness or real handwriting quality.

### Medium: known names still depend on selected redaction ranges

The local alias map is never included in the inference prompt. However, entering a student's real name does not automatically redact occurrences of that name in `text_ocr`; only selected or manually specified spans are replaced. The interface's absolute wording about names never being sent should be qualified, or exact known-name matches should be automatically included with a preview. Teacher review remains necessary for variants, OCR mistakes and indirect identifiers. No real data was used to test this scenario.

### Medium: native document parsing remains inside the application process

Pdfium and image parsers run in the same process as the workspace. File/page/image limits help bound normal resource usage but are not a parser sandbox. Move untrusted parsing to a restricted worker process before extending the prototype to institutional use. Cancellation is checked between pages rather than interrupting native parsing or OCR.

### Distribution and maintenance

- The installer remains unsigned and Windows-only. This review does not rebuild or install a release installer, publish changes, run remote CI, or validate real handwriting.
- RTen 0.27.0 and Skrifa 0.48.0 are newer than the current 0.26/0.47 requirements. They are intentionally deferred as incompatible 0.x-minor updates. RTen must be checked against Ocrs and pinned OCR models; Skrifa must be checked against font metrics and generated report layout.
- The installed pnpm 10.12.4 reports pnpm 12.10.1 as available. A major package-manager migration is deferred; update `packageManager`, developer prerequisites and both workflows together, then validate frozen-lockfile installation and packaging. The current frozen-lockfile installation passes.
- The two GTK-chain Rust advisories from the earlier review must remain visible; the supported Windows target must be checked separately from the all-platform lockfile.
- Inference requests have individual response/time limits but no shared inference semaphore. Many simultaneous IPC requests can compete for local model memory; add a bounded queue and cancellation if multi-submission batch assistance is implemented.
